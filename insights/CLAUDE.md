# Insights — Routing

Publishable POV articles. Every file here is a position the practice will
defend in public. Drafts live in `_backlog.md`. Published POVs are dated
files: `<topic>-<YYYY-MM-DD>.md`.

| File | What it is |
|---|---|
| `_backlog.md` | Candidate POVs surfaced by `weekly-practice-synthesis` |
| `from-contract-yaml-to-deployable-product-in-30-minutes-2026-05-09.md` | First POV: the DABs Golden Path argument |

## Conventions

- Every POV opens with **BLUF** in the first sentence.
- Cite authored vs curated IP separately. Never blur (Invariant #3).
- One claim per POV. Defend it from three counter-positions.
- End with a kill criterion: under what evidence would I retract?
- Sanitization: no employer / team / stakeholder / vendor / workspace ID.
- Banned style: leverage, utilize, synergies, deep dive, circle back.

## Workflow

1. `weekly-practice-synthesis` skill surfaces a candidate → `_backlog.md`.
2. Draft the POV in this directory under a working filename.
3. Three-pass verification (framework, BLUF, action) per `methodology/how-we-work.md`.
4. Sanitization lint must pass.
5. Promote to a dated filename when published.
