# 9-Question Canvas to Escape the Dashboard Factory

> **Source:** Sebastian Hewing. LinkedIn post — *"I used to run a very efficient dashboard share-share-share-share."*

## Core problem

Stakeholders ask for dashboards. You deliver. Then they ask for another. Then a slightly different cut. Then they export to Excel. **You're not building strategy — you're running a reporting helpdesk.**

## The 9 questions

| # | Question | What it forces you to define | Key insight |
|---|---|---|---|
| 1 | **Problem** | What's the real business pain? | If you can't name it in plain English, don't build anything yet. |
| 2 | **Users** | Who are you solving it for? | "The business" is **not** a user — be specific. |
| 3 | **UVP** | Why should users come to your team? | Instead of guessing, gut feel, or pulling numbers themselves. |
| 4 | **Solution** | What is the actual product? | Not a dashboard — it's the combination of *decisions, workflows, and systems* that drive action. |
| 5 | **Distribution** | How will users actually adopt it? | Bake it into their day-to-day. Motivate, enable, trigger. |
| 6 | **Systems** | What needs to be automated? | No one should need 3 meetings and 5 weeks to get data. |
| 7 | **Outcomes** | What are you actually measuring? | Revenue, savings, satisfaction, efficiency. Dashboards are just breadcrumbs. |
| 8 | **Costs** | What is this really costing? | The most expensive thing isn't the warehouse bill — it's the team burning time on low-impact work. |
| 9 | **People** | Do you have the right team? | Hiring and team design IS data strategy. |

## Mode shift

| 🏭 Dashboard Factory | 🚀 Strategic Data Team |
|---|---|
| Reactive to stakeholder requests | Proactive on business problems |
| Output = dashboards and reports | Output = decisions and actions enabled |
| Success = number of deliverables | Success = business outcomes moved |
| Team = SQL executors | Team = problem solvers |
| Value = unclear, assumed | Value = measured and communicated |

## When to use this in this practice

- **Self-Serve Analytics archetype** (`initiatives/archetypes/ARCHETYPE-D-…`) — defining what self-serve actually means beyond dashboards.
- **Executive narrative** — shifting the conversation from "how many reports" to "what outcomes are we enabling."
- **Team-design conversations** — Q9 is the entry point to changing skill mix.
- **Per-product gate** — every new data product should pass the 9-question test before build.

## How it applies in this practice

The 9-question canvas pairs cleanly with the 10Q Framework: 9Q answers *should we build this product?*; 10Q answers *can we ingest its sources?*. Together they decide go / no-go at the data-product level.
